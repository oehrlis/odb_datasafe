# Release Notes - v1.0.8

**Release Date:** 2026-07-03
**Type:** Patch (bug fix - Create+Delete path for vm-cluster-id change in ds_target_reregister.sh)

## Summary

v1.0.8 fixes a fundamental API constraint in `ds_target_reregister.sh`:
the OCI Data Safe `target-database update` endpoint refuses any change to
`vm-cluster-id` with `HTTP 400 InvalidParameter: vmClusterId cannot be updated`.

The fix introduces a Create→Delete code path that is automatically selected
when `--cluster` specifies a different cluster than the current target.

## Changes

### Fixed: `do_reregister()` — Create+Delete when vm-cluster-id changes

#### Root Cause

`vm-cluster-id` is immutable in the OCI Data Safe API after target creation.
Passing a new value via `target-database update --database-details` results in:

```json
{
  "code": "InvalidParameter",
  "message": "vmClusterId of target database cannot be updated",
  "status": 400
}
```

This affects any re-registration where the PDB moves to a different ExaCC cluster.

#### Fix

`do_reregister()` now detects whether `vm-cluster-id` is changing and routes
to the appropriate code path:

- **No cluster change** (`--service`, `--port`, `--display-name` only):
  `do_reregister_update()` — existing `target-database update` call (unchanged).

- **Cluster change** (`--cluster` specifies a different cluster OCID):
  `do_reregister_create_delete()` — three-step process:
  1. **Create** new target on new cluster (with updated `vm-cluster-id`,
     `service-name`, `listener-port`, new display name; preserves
     `description`, `connection-option`, `tls-config`, `freeform-tags`,
     `defined-tags` from the source target)
  2. **Delete** old target (`target-database delete --force`)

  If the create step fails, the old target is NOT deleted (safe fallback).
  If the delete step fails, both targets exist — the log shows both OCIDs
  for manual cleanup.

#### Display in dry-run plan

```text
[INFO]   VM Cluster:    'ocid1.vmcluster...old' → 'ocid1.vmcluster...new'
[INFO]   Strategy:      CREATE new target + DELETE old (vm-cluster-id is immutable via OCI API)
```

#### New fields captured from source target

Passed through to the create call: `connection-option`, `tls-config`, `freeform-tags`, `defined-tags`

## Upgrade Notes

No API or configuration changes. Drop-in replacement for v1.0.7.

When `--cluster` points to a different cluster, the operation now creates
a new Data Safe target and deletes the old one. Historical Data Safe data
(audit trails, findings, assessments) tied to the old target is not transferred.
