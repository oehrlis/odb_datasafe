# Release Notes - v1.0.10

**Release Date:** 2026-07-07
**Type:** Patch (bug fix - symlink-safe config permission check)

## Summary

v1.0.10 fixes `load_config()` in `lib/common.sh` to resolve symlinks before
checking config file permissions. On macOS, symlinks always report mode 0777
and cannot be `chmod`'d; the previous `find -perm` check evaluated the symlink
itself rather than the target file, causing valid 600 config files reached via
a symlink to be silently ignored with a spurious "group/world-writable" warning.

## Changes

### Fixed: `load_config()` — symlink-safe permission check

#### Previously (v1.0.9)

```bash
find "$config_file" -maxdepth 0 \( -perm -g+w -o -perm -o+w \)
```

When `$config_file` is a symlink, `find` evaluates the symlink's own mode
(0777 on macOS, immutable). A target file with mode 600 would still trigger
the warning and be ignored.

#### Now (v1.0.10)

```bash
_real_config_file=$(realpath "$config_file" 2>/dev/null \
    || readlink -f "$config_file" 2>/dev/null \
    || echo "$config_file")
find "$_real_config_file" -maxdepth 0 \( -perm -g+w -o -perm -o+w \)
```

The target file's permissions are checked. Falls back to the original path
when neither `realpath` nor `readlink -f` is available (portable).

## Upgrade Notes

No API or configuration changes. Drop-in replacement for v1.0.9.

Config files deployed as symlinks (e.g. managed via dotfiles) are now
accepted when the symlink target has mode 600.
