# Release Notes - v1.0.9

**Release Date:** 2026-07-03
**Type:** Patch (refactor - subprocess delegation in do_reregister_create_delete)

## Summary

v1.0.9 replaces the inline OCI API calls in `do_reregister_create_delete()` with
subprocess delegation to the existing `ds_target_register.sh` and
`ds_target_delete.sh` scripts, eliminating code duplication and ensuring that
dependency cleanup (audit trails, assessments, policies) runs correctly on delete.

## Changes

### Refactored: `do_reregister_create_delete()` — delegate to existing scripts

#### Previously (v1.0.8)

Inline OCI API calls:

- `target-database create` — duplicated creation logic from `ds_target_register.sh`
- `target-database delete --force` — deleted only the target, **no dependency cleanup**
  (orphaned audit trails, assessments, and security policies remained)

#### Now (v1.0.9)

Step 1 — `ds_target_register.sh` subprocess:

```text
--cluster   CLUSTER_OCID     (already resolved)
--compartment COMP_OCID      (from source target)
--sid       NEW_SID|CUR_CDB
--pdb       NEW_PDB|CUR_PDB
--service   <from new_db_details>
--port      <from new_db_details>
--display-name new_display_name
--ds-user   DS_USER
--ds-secret DS_SECRET
[--connector on-prem-connector-id from source connection-option]
[--description NEW_DESCRIPTION|CUR_DESCRIPTION]
```

`ds_target_register.sh` ignores existing DELETED-state targets by name
(lifecycle-state != DELETED filter in check_target_exists).

Step 2 — `ds_target_delete.sh` subprocess:

```text
--targets   TARGET_OCID
--compartment COMP_OCID
--force
```

Deletes audit trails, security assessments, and security policies associated
with the old target before removing the target itself — no orphaned resources.

### Added: credentials required for cluster migration

`validate_inputs()` now fails early with a clear message when `--cluster`
specifies a different cluster and `DS_SECRET` is empty:

```text
[ERROR] Cluster migration requires credentials.
        Provide --ds-secret or ensure a password file exists.
```

## Upgrade Notes

No API or configuration changes. Drop-in replacement for v1.0.8.

When migrating to a different cluster (`--cluster`), credentials (`--ds-secret`
or a discoverable password file) are now explicitly required.
